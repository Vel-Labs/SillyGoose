# Closeout Audit

## Go / No-Go

Go for local Ledger Security Key screen-share once a physical Ledger signs the WebAuthn registration/login prompt on the demo machine. The fallback path remains rehearsal-only.

## Verification

- `npm run lint`: passed.
- `npm run typecheck`: passed.
- `npm run build`: passed.
- Room/join API check: separate host and friend cookie jars created a room, loaded `/join/<room>`, then joined Player Two with a different local user.
- API flow check: demo session, room create, Player Two join, five legal moves, and X win returned `winner: "X"`.
- AI fallback check: `/api/ai/status` returned `offline-demo-fallback`; an AI-mode move produced a deterministic `O` response.
- Hardware caveat: physical Ledger button presses and browser WebAuthn prompts cannot be completed by automation in this environment.

## Flow Coverage

- Registration: implemented through SimpleWebAuthn.
- Login: implemented through SimpleWebAuthn.
- Ledger app preparation: implemented through DMK WebHID discovery/connect and `OpenAppCommand({ appName: "Security Key" })`.
- Dashboard protection: implemented with local session cookie and redirect.
- Add Intern Goose: implemented as a fresh WebAuthn challenge with marked fallback.
- New Game: implemented from the dashboard and creates a room code.
- Player Two join: implemented through `/join/<room-code>` with login/register redirect and a different-user join guard.
- Tic-Tac-Toe: implemented with local server state, legal move checks, win/draw detection, and verified player badges.
- Play vs AI: implemented as deterministic offline fallback unless MiniMax env readiness is present.

## Honest Boundaries

- This is not production IAM.
- This is not a wallet connector.
- This is not mainnet Web3.
- DMK is not the credential verifier.
- Local fallback is visible and must be narrated as rehearsal-only, not the acceptance path.

## Known Flakes

- Real Ledger Security Key verification still depends on browser/device availability and a user approving the physical device prompts during the live demo.
- Browser clicking on the Tic-Tac-Toe cells through Computer Use was inconsistent, so the full match proof was completed through the same local HTTP API that the UI uses.
- Running `next build` while `next dev` is serving can stale `.next` chunks; restart `npm run dev` after production builds.
